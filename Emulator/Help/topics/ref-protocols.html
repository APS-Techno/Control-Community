Protocols

The emulator communicates with SystemControl using three protocol layers: S7 over TCP for PLC access, virtual serial ports for instrument emulation, and direct TCP for network instruments. Each layer is described below.

Memory Areas

The S7 server exposes four memory areas that SystemControl reads and writes:

DB (Data Block)0x84Analog values: pressures, flows, positions, turbo status

Virtual Serial Ports

ParameterValue
APISystem.IO.Ports.SerialPort
Drivercom0com or FVSP null-modem pairs
Read ModeAsynchronous (event-driven)
Peer DetectionDSR (Data Set Ready) signal

Each emulated serial device opens the device-side port (e.g., COM121) of a virtual null-modem pair. SystemControl opens the host-side port (e.g., COM21). Data written to one port appears on the other, creating a transparent serial link without physical hardware.

Framing Modes

The serial adapter supports five framing modes that determine how incoming bytes are assembled into complete messages:

DSR Peer Detection

The emulator uses the DSR (Data Set Ready) serial handshake line to detect when SystemControl has opened its side of the port pair. This prevents the emulator from sending data before a client is connected and avoids buffer overflow on unconnected ports.

TCP Serial

ParameterValue
ProtocolSCPI (Standard Commands for Programmable Instruments)

Bind Address127.0.0.1 (configurable)
Port5025

TCP serial devices use direct TCP rather than virtual serial ports. It accepts SCPI command strings terminated with a line feed character. The emulator binds a TCP listener on the configured address and port, accepting connections from SystemControl. Multiple commands can be sent per connection.
