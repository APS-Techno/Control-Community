Network Configuration

The emulator hosts a TCP server that mimics the S7-200 PLC. SystemControl connects to it using the same IP address it would use for real hardware, so a loopback alias must be configured on the development machine. The demo power supplies listen on 127.0.0.1 and need no alias.

Required Addresses

Device IP Address TCP Port Protocol
S7-200 PLC 192.168.127.208 102 S7comm (ISO-on-TCP)
PSU1, PSU2 (demo power supplies) 127.0.0.1 5025, 5026 SCPI over TCP

Creating Loopback Aliases

Open the emulator, click the Prepare System button on the Config tab, and choose Fix All. The panel reads the required IP addresses from EmulatorConfig.xml and creates aliases on Loopback Pseudo-Interface 1 in a single elevated operation.

If you prefer to add aliases manually, run the following from an elevated command prompt:

netsh interface ip add address "Loopback" 192.168.127.208 255.255.255.0
Note: The interface name ("Loopback") may vary depending on how the adapter was installed. Use netsh interface ip show config to list interface names and substitute the correct one.

Installing a Loopback Adapter

If no loopback adapter exists on the system, create one through Device Manager:

  1. Open Device Manager.
  2. Select Action → Add legacy hardware.
  3. Choose Install the hardware that I manually select from a list.
  4. Select Network adapters.
  5. Pick Microsoft as the manufacturer and Microsoft KM-TEST Loopback Adapter as the model.
  6. Complete the wizard. The adapter appears under Network adapters.
  7. Rename the adapter to Loopback (optional but recommended for the netsh commands above): 
    netsh interface set interface name="Ethernet 2" newname="Loopback"

Firewall Rules

If Windows Firewall is active, allow inbound connections on the required ports. Run from an elevated prompt:

netsh advfirewall firewall add rule name="APS Emulator - TCP 102" dir=in action=allow protocol=tcp localport=102

Verifying the Configuration

After adding the alias and firewall rule, confirm reachability by pinging the address:

ping 192.168.127.208

A successful reply from 127.0.0.1 (or the loopback adapter) confirms the alias is active. If the ping fails, re-check the interface name used in the netsh commands.
