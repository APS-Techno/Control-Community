Starting & Stopping

Launching

Run APSSystemEmulator.exe from the build output directory. The Emulator enforces a single-instance mutex — if an instance is already running, the new process will display a message and exit. This prevents port conflicts and duplicate device emulation.

Startup Sequence

When the Emulator launches, it performs the following steps in order:

  1. Load configuration — reads EmulatorConfig.xml and HWConf.Emulator.xml to discover all devices, COM port mappings, and physics parameters
  2. Instantiate devices — creates emulator instances for every PLC, serial device, and TCP instrument defined in the configuration
  3. Start protocol servers — opens the S7 TCP listener (port 102), binds virtual COM ports, and starts TCP serial servers
  4. Begin simulation tick — starts the 100ms tick loop that updates physics, device states, and PLC registers
  5. Show dashboard — displays the main window with the Vacuum, Power Sources, Configuration, and Log tabs

Reconnect Ports

If virtual COM ports become disconnected (for example, after a USB adapter reset or com0com/FVSP reconfiguration), use the Reconnect Ports button on the Configuration tab. This closes and re-opens all serial port connections without restarting the entire application.

Connecting Control Software

To connect the APS System Control software to the Emulator:

  1. Start the Emulator first and wait for the dashboard to appear
  2. Verify the Configuration tab shows all protocol servers running and ports open
  3. Launch APS System Control — it will connect to the same TCP ports and virtual COM ports that the Emulator is serving
  4. Control should detect all devices within one or two PLC poll cycles (200–400ms)

Stopping

Close the Emulator window or use the standard window close button. The shutdown sequence:

  • Stops the simulation tick loop
  • Closes all virtual COM port connections
  • Shuts down the S7 TCP listener and TCP serial servers
  • Releases the single-instance mutex

Control software will detect the disconnection on its next poll cycle and report communication errors. It is safe to restart the Emulator and reconnect without restarting Control.
